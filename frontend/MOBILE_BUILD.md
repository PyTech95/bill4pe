# BILL4PE Mobile — Android + iOS

BILL4PE uses **one React frontend and one FastAPI/MongoDB backend** for web, Android and iOS. The mobile apps are native Capacitor shells around the same production frontend code, so the billing, wallet, receipt verification, Razorpay and account logic stays on the same backend.

## App identity

- App name: `BILL4PE`
- Android package: `com.bill4pe.app`
- iOS bundle identifier: `com.bill4pe.app`
- Framework: Capacitor 7
- Minimum iOS target: generated by Capacitor 7 (iOS 15+)

## 1. Configure the backend URL

Create `frontend/.env` from `.env.example`:

```env
REACT_APP_BACKEND_URL=https://api.yourdomain.com
ENABLE_HEALTH_CHECK=false
```

Do **not** add `/api` to the URL; `src/lib/api.js` adds `/api` automatically.

The deployed backend should allow the web domain plus native Capacitor origins when CORS is restricted:

```env
CORS_ORIGINS=https://bill4pe.com,https://www.bill4pe.com,https://localhost,capacitor://localhost
```

Use HTTPS in production.

## 2. Install and generate both native projects

```bash
cd frontend
npm install --legacy-peer-deps
npm run mobile:prepare
```

`mobile:prepare` builds the React frontend, generates `android/` and `ios/` if they are not present, runs `cap sync`, and applies the required camera, microphone, location and UPI-app declarations.

Re-run after frontend/plugin changes:

```bash
npm run mobile:sync
```

Quick configuration check:

```bash
npm run mobile:doctor
```

## 3. Android / Google Play

```bash
npm run mobile:android
```

Android Studio opens. For Play Store release:

1. Set `versionCode` and `versionName` in `android/app/build.gradle`.
2. `Build` → `Generate Signed Bundle / APK`.
3. Choose **Android App Bundle (AAB)** for Google Play.
4. Create/select your release keystore and keep it safely; losing it can block future app updates.
5. Upload the generated `.aab` in Google Play Console.

For a local debug APK:

```bash
cd android
./gradlew assembleDebug          # macOS/Linux
# or gradlew.bat assembleDebug   # Windows
```

## 4. iOS / Apple App Store

An iOS App Store build requires **macOS + Xcode + an Apple Developer account**.

```bash
npm run mobile:ios
```

Then in Xcode:

1. Open the generated `ios/App/App.xcworkspace` (or the project Xcode opens).
2. Select the `App` target.
3. Signing & Capabilities → choose your Apple Developer Team.
4. Confirm bundle identifier `com.bill4pe.app`.
5. Set Version and Build number.
6. Select `Any iOS Device (arm64)`.
7. `Product` → `Archive`.
8. In Organizer choose `Distribute App` → `App Store Connect`.

## Mobile behavior already handled

- First authenticated use requires the existing **4-digit BILL4PE Wallet PIN setup**.
- Same backend/API and MongoDB database as the website.
- Receipt/payment proof upload works through native camera/photo chooser and existing backend verification.
- GPS uses native location permission in Android/iOS and falls back to browser geolocation on web.
- Microphone permission supports existing voice expense notes.
- Status bar, splash screen, Android hardware Back button and safe-area/notch handling are included.
- Bottom navigation and forms are hardened for small Android devices, iPhone notch/Dynamic Island and home-indicator areas.
- Razorpay continues to use the existing backend order/signature verification flow; secrets remain only on backend `.env`.
- Mobile app never needs MongoDB credentials or Razorpay secret key in its `.env`.

## Security rule

Only this belongs in the frontend/mobile `.env`:

```env
REACT_APP_BACKEND_URL=https://api.yourdomain.com
```

Never put any of these in the mobile frontend:

- `MONGO_URL`
- `JWT_SECRET`
- `RAZORPAY_KEY_SECRET`
- `GEMINI_API_KEY`

Those remain on the backend server only.
